# HG113 产品方案

更新时间：2026-07-08

这份文档记录当前主线的产品方向。以后继续开发时，默认以 HG113 电话、ESP32-C3、
电脑端控制台和蓝牙音频模块这一套结构为准。

## 目标

围绕 HG113 做一个稳定、简单、可继续扩展的 AI 桌面电话：

1. ESP32-C3 读取电话摘挂机开关状态。
2. ESP32-C3 通过 Wi-Fi 向电脑发送轻量状态数据。
3. 电脑端负责网页、波形、配置、业务逻辑和 AI hook。
4. Codex 或其他 AI 工具完成任务后，可以通过本地 hook 让电话响铃和亮灯。
5. 后续接入豆包全双工语音模型时，手柄音频走蓝牙音频模块，不走 ESP32-C3。

## 页面结构

网页应该比现在的调试台更简洁，只保留运行和现场排查必需的东西。

### 1. 状态显示

- 判定后的电话状态：抬起 / 按下。
- 原始 GPIO 状态：HIGH / LOW。
- 一块 GPIO 数字波形显示区域。
- 可选显示：Wi-Fi、ESP32 IP、蜂鸣器状态、LED 状态。

### 2. 配置与测试

- GPIO 配置：摘挂机输入 GPIO、蜂鸣器 GPIO、LED GPIO。
- 蜂鸣器测试：响一下、持续响、停止。
- LED 测试：点亮、熄灭。
- 摘挂机判定方案：
  - 方案 1：`HIGH = 按下`，`LOW = 抬起`。
  - 方案 2：`LOW = 按下`，`HIGH = 抬起`。

### 3. 配套动作配置

这里的“业务模式”和原始 GPIO 判定方案分开。GPIO 判定只回答“现在电话是抬起还是按下”，
业务模式决定“这个状态变化要触发什么动作”。

#### 方案 A：输入法 / Codex 模式

沿用当前快捷键和 AI 完成提醒思路。Codex 执行完成后通知本地控制台：

```text
Codex 任务完成
  -> POST /api/ai/hook
  -> alerting = true
  -> 蜂鸣器响
  -> LED 亮
```

停止规则：

```text
用户抬起电话
  -> alerting = false
  -> 蜂鸣器停止
  -> LED 熄灭
```

这个模式下，电话就是一个实体任务完成提醒器。提醒不应该只靠超时自动消失，
而是要等用户真正把电话抬起来。

#### 方案 B：豆包聊天模式

把电话手柄作为豆包全双工语音模型的入口。

触发流程：

```text
用户抬起电话
  -> 开始语音会话或语音报告
  -> 直接播报待报告内容
```

播报要求：

- 直接读取内容。
- 不额外添加寒暄、总结或解释，除非上层流程明确要求。

后续这个模式可以扩展成真正的全双工语音对话。

## AI Hook 约定

本地控制台提供这两个入口：

```text
POST /api/ai/hook
POST /hook
```

建议请求体：

```json
{
  "source": "codex",
  "text": "后续需要播报的内容"
}
```

当前行为：

- 通过 ESP32 命令链路触发蜂鸣器和 LED。

目标行为：

- 保存待播报文本。
- 进入 `alerting = true`。
- 蜂鸣器和 LED 保持工作，直到检测到电话被抬起。
- 电话抬起后停止提醒，并读取保存的内容。

## 状态模型

推荐电脑端维护这些核心状态：

```text
raw_gpio_level: HIGH | LOW
hook_state: lifted | pressed
business_mode: codex | doubao
alerting: true | false
pending_report_text: string | null
buzzer: on | off
led: on | off
```

重要边界：

- 固件保持简单，只负责读 GPIO、上报状态、执行硬件命令。
- 业务解释放在电脑端后端。
- 网页负责展示状态和发送命令，不承载核心状态机。

## 硬件基线

已验证接线以 [HG113 连接方式](HG113_CONNECTION_MANUAL.md) 为准。

当前默认值：

```text
摘挂机输入：GPIO0
蜂鸣器：    GPIO21
LED：       GPIO20
```

当前已经测通的摘挂机开关接法：

```text
GPIO0 -> HG113 六脚簧片开关 6 脚
GND   -> HG113 六脚簧片开关 2 脚
```

## 开发顺序

1. 把当前调试台收敛成更简洁的 HG113 控制台页面。
2. 将摘挂机判定方案和业务模式做成明确的顶层设置。
3. 将 AI hook 从“一次性响一下”改成“持续提醒”。
4. 只有检测到电话抬起时才清除提醒。
5. 保存并显示待播报内容。
6. 增加文字转语音播报。
7. 接入豆包全双工语音模式。

## 当前主线不做的事

- 不再把 BLE HID 作为主控制链路。
- 不让 ESP32 承载网页。
- 不让 ESP32-C3 处理手柄音频。
- 不把电话外线高压接入 ESP32。
