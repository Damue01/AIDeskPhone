# 真实地球数据接入方案

## 目标

当前方向收敛为“真实地图地球 + 云层开关预留 + 城市级缩放”：

- 主入口使用 `index.html`，把 Three.js 视觉地球和 MapLibre 真实地图融合在同一页。
- 默认地球延续参考设计的干净球体、地表文字和弧形文字效果。
- 放大到贴图清晰边界前，过渡到真实卫星地图，继续进入城市、市区和街区级缩放。
- 云层暂不启用，避免把科学云量图层误当成真实白色云视觉。

## 当前实现

```text
主页面：web/variant-earth-command-center/index.html
探索页：web/variant-earth-command-center/real-map.html
```

`index.html` 现在承担主体验：

- Three.js 地球作为默认地球态，保留拖拽旋转、惯性、轻量缩放和参考页文字效果。
- 地球纹理使用 EOX WMS 的 `s2cloudless-2024` 图层，尽量让球体和后续卫星地图视觉接近。
- MapLibre 负责真实地图态，底图使用 EOX Sentinel-2 cloudless 2024 WMTS 卫星瓦片。
- 地图态使用城市标签层提示当前位置，不切回传统街道图。
- `real-map.html` 保留为方案探索和回归对照，不再作为必须跳转的主路径。

## 数据源

当前使用的真实地图数据源：

```text
EOX WMS:
https://tiles.maps.eox.at/wms

EOX WMTS:
https://tiles.maps.eox.at/wmts/1.0.0/s2cloudless-2024_3857/default/g/{z}/{y}/{x}.jpg

图层:
s2cloudless-2024
```

这个方案的好处：

- 不需要前端 API key，适合原型阶段快速验证。
- 卫星图比街道图更接近“真实地球”的用户预期。
- cloudless 图层减少云遮挡，避免把“去除照片里的云”做成产品需求。

需要注意：

- 公共瓦片服务不等于生产级 SLA；正式上线前应加缓存代理、失败兜底和速率控制。
- Sentinel-2 cloudless 不是实时卫星照片，适合做真实地图底图，不适合承诺实时地表状态。
- 浏览器直连第三方瓦片时，需要在产品说明或页面 attribution 中保留数据来源。

## 云层决策

当前不启用云层。

之前测试过 NASA GIBS `MODIS_Terra_Cloud_Fraction_Day`。它是云量 / 云覆盖科学图层，会出现红色、粉色等数据色，不是常见地图 App 里的真实白色云层视觉。

因此现在不做：

- 不做实时卫星照片级地球。
- 不要求去除卫星照片里的云。
- 不把科学配色云量图层叠到产品默认视觉上。

后续如果恢复云层，建议只考虑两类方案：

- 使用已经视觉化为白色云图的天气瓦片服务。
- 在服务端拉取科学云量数据，统一做调色、透明度和缓存处理，再交给前端展示。

## 交互原则

- 缩放过程应尽量保持同一视觉对象的连续性：在地球贴图变模糊前切到卫星地图。
- 从地球态进入地图态时，必须按当前地球中心位置换算经纬度，避免中国放大后跳到非洲一类偏差。
- 地图态缩小时可以回到地球态，但要保留大致中心位置，避免用户迷路。
- 地图文字层要克制，只提供城市识别，不遮挡卫星图主体。
- 不添加轨道、半透明圆环、散点星环等额外装饰；语言输入 / 输出的可视化优先考虑文字亮度、密度、波动和沿弧线的节奏。

## 风险

- MapLibre 滚轮事件在嵌入页面里需要继续手工调体验，自动化浏览器此前不能稳定复现所有滚轮路径。
- EOX 公共瓦片在生产环境需要确认授权、缓存和可用性。
- 低缩放地球纹理与高缩放瓦片之间仍可能存在色彩和投影差异，需要靠过渡、曝光和中心定位继续打磨。
