# HG113 产品方案

更新时间：2026-07-08

这份文档记录当前主线的产品方向。以后继续开发时，默认以 HG113 电话、ESP32-C3、
电脑端控制台和蓝牙音频模块这一套结构为准。

## 目标

围绕 HG113 做一个稳定、简单、可继续扩展的 AI 桌面电话：

1. ESP32-C3 读取电话摘挂机开关状态。
2. ESP32-C3 通过 Wi-Fi 向电脑发送轻量状态数据。
3. 电脑端负责网页、波形、配置、业务逻辑和 AI hook。
4. Codex 或其他 AI 工具完成任务后，可以通过本地 hook 触发接线员模式提醒。
5. 后续接入豆包全双工语音模型时，手柄音频走蓝牙音频模块，不走 ESP32-C3。

## 页面结构

网页应该比现在的调试台更简洁，只保留运行和现场排查必需的东西。

### 1. 状态显示

- 判定后的电话状态：抬起 / 按下。
- 原始 GPIO 状态：HIGH / LOW。
- 一块 GPIO 数字波形显示区域。
- 可选显示：Wi-Fi、ESP32 IP、蜂鸣器状态、LED 状态。

### 2. 配置与测试

- GPIO 配置：摘挂机输入 GPIO、蜂鸣器 GPIO、LED GPIO。
- 蜂鸣器测试：响一下、持续响、停止。
- LED 测试：点亮、熄灭。
- 摘挂机判定方案：
  - 方案 1：`HIGH = 按下`，`LOW = 抬起`。
  - 方案 2：`LOW = 按下`，`HIGH = 抬起`。

### 3. 配套动作配置

这里的“业务模式”和原始 GPIO 判定方案分开。GPIO 判定只回答“现在电话是抬起还是按下”，
业务模式决定“这个状态变化要触发什么动作”。

#### 方案 A：文字输入 / 接线员模式

沿用当前快捷键和任务完成提醒思路。Codex 执行完成后通知本地控制台：

```text
Codex 任务完成
  -> POST /api/ai/hook
  -> alerting = true
  -> 蜂鸣器和 LED 同步 1 秒响/亮、4 秒停/灭循环
```

停止规则：

```text
用户摘机接听
  -> alerting = false
  -> 蜂鸣器停止
  -> LED 熄灭
```

无人接听规则：

```text
约 90 秒无人摘机
  -> 普通 1 秒响、4 秒停的节奏停止
  -> 切换为忙音节奏
  -> 摘机或手动停止后关闭蜂鸣器和 LED
```

这个模式下，电话就是一个实体任务完成提醒器，不再填写“待播报内容”。
hook 只负责告诉本地控制台“任务结束了，可以开始呼叫”。

这个模式后续拆成两个动作：

```text
用户摘机
  -> 执行“开始输入”快捷键

用户挂机
  -> 执行“结束/提交”快捷键
```

如果当前正在接听回话，回话优先级高于快捷键。也就是说，摘机接听回话时不触发开始输入，
挂机停止回话时不触发结束/提交。

#### 方案 B：豆包聊天模式

把电话手柄作为豆包全双工语音模型的入口。

触发流程：

```text
用户抬起电话
  -> 开始本地录音
  -> 建立 BigASR WebSocket，持续上传麦克风音频

用户保持摘机并暂停说话
  -> 停止本轮录音
  -> 收尾当前流式 ASR
  -> 如果仍然摘机，直接播放回话

用户按下电话
  -> 如果 Agent 正在播报，暂停当前回报并重新进入回拨
  -> 如果用户语音已经提交或正在识别，后台继续处理
  -> 完成后通过 LED/蜂鸣器回拨
```

播报要求：

- 直接读取内容。
- 不额外添加寒暄、总结或解释，除非上层流程明确要求。

后续这个模式可以扩展成真正的全双工语音对话。

当前第一版正式实现：

- 仍然不改变底层 `PRESSED / RELEASED` 协议。
- `business_mode = doubao` 时，`RELEASED` 触发摘机通话，静音自动提交一轮语音。
- `PRESSED` 在 Agent 模式里按场景解释：播报中表示停止当前播报；录音/识别/执行中表示挂断听筒但后台继续完成任务。
- 录音保存到本地 `data/recordings/`，该目录不提交。
- 录音依赖 `sounddevice`；如果未安装或没有可用麦克风，控制台只记录错误，不影响其他功能。
- ASR 优先使用流式 WebSocket，默认 200ms 分包；失败时回退文件识别。结果先进入本地状态和动作日志；后续再接本地 Agent。

#### 方案 C：Agent 通讯员模式

这个模式下，电话对面是一个“通讯员”Agent：用户是首长，摘机后下达命令，Agent 负责打开软件、
操作本机暴露的接口、整理信息并回报结果。

权限原则：

- 默认允许打开软件、修改本地配置、调用本地接口、整理文件和生成内容。
- 对外发送、删除大量数据、公开发布等动作可以继续加确认。
- 付款、转账、购买、资金相关操作必须确认，不自动执行。

### 豆包 / 火山引擎路线

直接聊天优先不自建模型链路：

```text
抬起电话
  -> 触发豆包客户端快捷键

按下电话
  -> 触发豆包客户端结束/提交快捷键
```

这样最省成本，也复用豆包客户端现成的全双工体验。

自建链路只用于更需要控制的任务型能力：

- Ark 角色模型：把 Codex hook 或任务完成文本润色成“通讯员回报”，默认使用 `doubao-seed-character-260628`，凭据使用 `ARK_API_KEY`；如果确认 `VOLCENGINE_API_KEY` 同时也是 Ark Chat Completions key，可显式开启兼容复用。
- 火山引擎 ASR：把电话命令转成文字。
- Agent：执行本机软件、接口和配置操作。
- 火山引擎豆包 TTS 2.0：把任务结果转成回话音频，默认优先用 SSE PCM 块做流式播放，默认音色按“甜美桃子 2.0”配置。
- 回话队列：任务完成后打回电话，抬起后播放。

API key 不写入仓库。后续接入时使用本地 `.env` 或本机配置文件，例如：

```text
VOLCENGINE_API_KEY=...
DOUBAO_TTS_SPEAKER=zh_female_tianmeitaozi_uranus_bigtts
```

如果使用旧版语音控制台凭据，再改填 `VOLCENGINE_APP_ID` 和 `VOLCENGINE_ACCESS_TOKEN`。
新版 API Key 存在时，控制台会优先使用新版 `X-Api-Key` 接入。

本地控制台语音接口：

```text
GET  /api/speech/status
POST /api/speech/transcribe-file
{"path":"C:\\path\\to\\audio.wav"}

GET  /api/voice/status
POST /api/voice/start
POST /api/voice/stop
```

TTS 不单独暴露给页面调用；回话播放时会优先尝试豆包 TTS 2.0，未配置或失败时回退到 Windows TTS / 模拟播放。

## 回话功能

回话是独立于输入法模式和 Agent 模式的全局能力。

```text
任务完成
  -> 生成一条回话任务
  -> 加入回话队列
  -> 铃声和灯光呼叫
  -> 用户摘机
  -> 按队列顺序播放
```

规则：

- 回话队列按先入先出播放。
- 同一时间只允许一个回话处于播放中。
- 播放中挂机，立即停止当前播放。
- 如果挂机时队列里还有未播放内容，控制台重新进入呼叫提醒。
- 回话接听期间不触发输入法快捷键，避免“听回报”和“开始输入”互相干扰。
- 当前本地第一版使用 Windows 语音播放或模拟播放；后续可替换成豆包 TTS，并把音频输出路由到电话蓝牙模块。

## 接线员 Hook 约定

本地控制台提供这两个入口：

```text
POST /api/ai/hook
POST /hook
```

建议请求体：

```json
{
  "source": "codex",
  "text": "可选，要播报或整理成回话的内容"
}
```

当前行为：

- 将 hook 文本提取后优先交给 Ark 角色模型润色成通讯员回报，再加入队列；模型失败时保留原文。
- 如果回话开关开启，进入 `alerting = true`。
- 蜂鸣器和 LED 同步按 `1 秒响/亮 -> 4 秒停/灭` 循环。
- 灯光是低频慢闪，不是高频快速频闪。
- 约 90 秒无人接听后切换忙音节奏。
- 电话摘机后，蜂鸣器和 LED 全部关闭，并开始播放队列里的回话。

Codex hooks 配置和脚本见 [Codex 接线员 hook 配置](CODEX_OPERATOR_HOOK.md)。

## 状态模型

推荐电脑端维护这些核心状态：

```text
raw_gpio_level: HIGH | LOW
hook_state: lifted | pressed
business_mode: codex | doubao
alerting: true | false
alert_phase: idle | ring | pause | busy
buzzer: on | off
led: on | off
reply_queue: queued reply[]
active_reply: reply | null
playback_active: true | false
callback_session_active: true | false
```

底层通信协议继续使用原来的两个状态，不新增协议名：

```text
PRESSED  = 按下
RELEASED = 抬起
```

所有业务动作都由这两个信号触发：

```text
RELEASED
  -> 输入法模式：如果有回话则接听并播放，否则执行摘机快捷键
  -> Agent 模式：如果有回话则接听并播放，否则开始摘机通话

PRESSED
  -> 输入法模式：如果正在播放则停止播放，否则执行按下快捷键
  -> Agent 模式：如果正在播报则停止当前播报；如果正在录音/识别/执行则提交或保留后台任务，完成后回拨
```

本地模拟 / 外部信号入口：

```text
POST /api/simulate/release
POST /api/simulate/press
```

页面和产品文案可以显示“抬起 / 按下”，但不改变底层通信协议。

重要边界：

- 固件保持简单，只负责读 GPIO、上报状态、执行硬件命令。
- 业务解释放在电脑端后端。
- 网页负责展示状态和发送命令，不承载核心状态机。

## 硬件基线

已验证接线以 [HG113 连接方式](HG113_CONNECTION_MANUAL.md) 为准。

当前默认值：

```text
摘挂机输入：GPIO0
蜂鸣器：    GPIO21
LED：       GPIO20
```

当前已经测通的摘挂机开关接法：

```text
GPIO0 -> HG113 六脚簧片开关 6 脚
GND   -> HG113 六脚簧片开关 2 脚
```

## 开发顺序

1. 把当前调试台收敛成更简洁的 HG113 控制台页面。
2. 将摘挂机判定方案和业务模式做成明确的顶层设置。
3. 将 hook 提醒做成 `1 秒响/亮 -> 4 秒停/灭` 的接线员呼叫节奏。
4. 只有检测到电话摘机或手动停止时才清除提醒。
5. 约 90 秒无人接听后切换忙音。
6. 接入回话队列、播放中挂机停止、模拟页手动造摘机/挂机和回话。
7. 后续再接入豆包 TTS、音频设备选择和全双工 Agent 模式。

## 当前主线不做的事

- 不再把 BLE HID 作为主控制链路。
- 不让 ESP32 承载网页。
- 不让 ESP32-C3 处理手柄音频。
- 不把电话外线高压接入 ESP32。
